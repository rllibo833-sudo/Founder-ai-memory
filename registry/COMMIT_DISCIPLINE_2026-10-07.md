# COMMIT DISCIPLINE

Status: **FOUNDER-APPROVED / ACTIVE**

A commit is evidence of a deliberate system change, not a progress counter.

Every material commit must have:

1. a concrete purpose;
2. a named repository owner;
3. a user/problem or governance reason;
4. verification appropriate to the change;
5. synchronization when the change affects shared architecture or truth.

Do not create commits merely to:

- increase activity;
- make the project look alive;
- add decorative UI;
- create synthetic tests without a real capability need;
- satisfy an arbitrary progress percentage.

Preferred sequence:

**REAL NEED → SMALLEST USEFUL CHANGE → VERIFY → COMMIT → SYNC → REPORT**

If no real need or evidence justifies the change, do not commit it.
