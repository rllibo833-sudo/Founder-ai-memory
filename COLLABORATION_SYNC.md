# Collaboration Sync Contract

The project has one collaboration proposition expressed consistently across three repositories.

## Canonical proposition

**PUBLIC attracts and explains. CORE qualifies and executes. MEMORY preserves continuity. The Founder accepts consequential commitments.**

The project should be discoverable by people who can bring:

- a concrete paid problem;
- a credible collaboration or partnership pathway;
- technical capability;
- research/domain evidence;
- a pilot;
- an implementation or funding pathway.

## Anti-hype rule

The system must never imply that collaboration, partnership, customers, funding, payment, or physical implementation exists unless evidence verifies it.

Current truth remains:

- customers: 0 verified;
- partners: 0 verified;
- payment: Rp0 verified;
- verified margin: Rp0;
- physical implementation: not claimed.

## Synchronization rule

When collaboration-related truth changes:

1. **CORE** records the canonical evidence/status.
2. **MEMORY** records durable Founder decisions and continuity.
3. **PUBLIC** exposes only the verified, externally appropriate summary.

Do not create contradictory opportunity, partner, revenue, or maturity claims across repositories.

## Founder boundary

The Founder remains Originator / System Owner / Strategic Director / Reviewer / Final Accepter / Economic Beneficiary.

AI handles research, analysis, implementation, testing, documentation, and repetitive operational work.

Consequential external commitments remain behind the Founder Gate.

## Collaboration quality standard

The project should optimize for **inbound relevance**, not vanity traffic.

A strong inbound signal is:

**REAL NEED / CAPABILITY / PATHWAY → EVIDENCE → QUALIFICATION → FOUNDER GATE**

Generic praise is not partnership proof.

**No Proof, No Claim.**
